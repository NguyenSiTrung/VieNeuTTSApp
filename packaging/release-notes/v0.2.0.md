## VieNeuTTS v0.2.0 — Optional Qwen Engines: Multilingual TTS, GGUF Formats & Engine-Aware Workflows

This is the first feature release since v0.1.16, and it turns the app from a
single-engine Vietnamese/English tool into a **multi-engine workstation**.
Beside VieNeu (still the default), two opt-in **Qwen 0.6B** profiles add ten
languages — either nine built-in speakers (**CustomVoice**) or your own
enrolled clones (**Base**) — in **two interchangeable model formats**: the
default **GGUF** path on a pinned native `qwentts.cpp` runtime, or the original
**official PyTorch weights**. Both install on demand from Settings behind
checksum-verified manifests, run in an isolated model-host subprocess, and
follow the same Text, Paragraph/Batch, Audiobook, Subtitle, Studio, cache and
export surfaces as VieNeu — with engine-stamped provenance, so one engine's
render is never replayed as another's.

Nothing Qwen-related is bundled: the app's own dependency lock is unchanged and
the release pipeline now asserts the frozen bundle carries no PyTorch/Qwen
stack.

### Added — Optional Qwen engines (CustomVoice / Base)

- **Two opt-in engine profiles** beside VieNeu: **Qwen CustomVoice 0.6B** (10
  languages — Chinese, English, Japanese, Korean, German, French, Russian,
  Portuguese, Spanish, Italian — with 9 fixed speakers) and **Qwen Base 0.6B**
  (the same languages, with your own voice clones enrolled from a 3–8 s
  reference clip plus its transcript). Vietnamese is not a Qwen language, which
  is why VieNeu stays the fresh-install and migrated-settings default.
- **Explicit, global engine selection.** The active profile is picked in
  Settings and never guessed from text; switching is refused while a job is
  running or queued, and exactly one model owner is resident at a time.
- **One capability table as the single source of truth** — voices, languages,
  cloning support, readiness and runtime — with every surface (pickers,
  synthesis gates, caches, exports) deriving from it instead of re-deciding.
- **Managed, verified installs.** Both the runtime and the models install from
  Settings with state, size and free-space requirement shown before you start,
  resumable downloads, **offline-pack import**, and size + SHA-256 manifest
  verification; an interrupted install is never promoted into place. The
  official-weights path is ~1.5–3 GB of runtime plus ~2.5 GB of model per
  profile (~4.3 GB for both, which share ~683 MB).
- **Isolated model-host subprocess** (`--qwen-host`) speaking a framed IPC
  protocol: the app's own environment is never modified, a crashed host is
  restarted on the next job instead of taking the app down, generation emits
  liveness heartbeats, cancellation escalates from a cooperative request to
  silence-based termination, and the host's machine footprint (threads, RSS) is
  governed per job.
- **Every surface follows the active profile** — Text, Paragraph/Batch,
  Audiobook, Subtitle, Audio Studio, caches and exports. VieNeu's own default
  voice and temperature controls read as unavailable *with the reason on
  screen* under a Qwen profile, and the Text tab replaces its emotion-tag chips
  with the reason (both 0.6B checkpoints ignore `instruct`).
- **Profile-scoped clones.** Base clones are stored as a plain WAV +
  transcript and re-derived by whichever host serves them, so an enrolled clone
  works under either model format.
- **Engine-stamped provenance.** Audiobook/subtitle caches and Studio clips
  carry the engine identity that produced them; a clip from another engine is
  flagged and offers a one-click switch to the profile it was rendered with.
- **Setup guidance instead of dead ends.** An unready profile points at the
  exact Settings card and action (runtime, model, quantization) rather than
  failing at synthesis time.
- **Batch synthesis for export jobs** (bounded by total characters) and
  audition previews that speak in the job's language rather than fixed
  Vietnamese.

### Added — GGUF format variant (default for Qwen)

- **GGUF is now the default format for the Qwen family**, with the `Q8_0` chip
  marked as recommended; the official full weights stay one click away with
  their cost stated on screen, and an explicit format choice is persisted and
  never overridden.
- **Checksum-locked native runtime packs** on the pinned `qwentts.cpp` engine,
  published for **Windows x64 CPU** (8 MiB), **Linux x64 CPU** (18 MiB),
  **Apple Silicon CPU** (5 MiB) and **Apple Silicon Metal** (7 MiB) — installed
  in one click from the Settings runtime card or imported as a folder offline.
  A pack whose native library cannot load is reported as an incomplete runtime
  with a **Repair** action (a re-verified reinstall, not a stack trace).
- **Per-variant model installs**: one talker GGUF per profile and quantization
  (0.6–1.0 GB) plus one tokenizer GGUF per quantization shared by both profiles
  (291 MB `Q8_0` / 255 MB `Q4_K_M`) — a profile pair at the same quantization
  never duplicates it.
- **Variant-aware everything.** Readiness, pickers and provenance know the
  exact build identity: a `Q4_K_M` render is never replayed as `Q8_0`, and
  switching format is explicit, never automatic.
- **Isolated GGUF host** (`--qwen-gguf-host`) on the same framed protocol, with
  the app's `auto`/`mps` device spellings resolved to the native vocabulary, a
  structured non-fatal refusal for backends a pack does not ship, and the same
  cancellation/restart lifecycle guarantees as the Python host.
- **CUDA without a GPU runner.** CI has none, so CUDA cells stay unpublished —
  but a source checkout can build and import one locally, documented in
  [docs/qwen-gguf-runtime-local-build.md](../../docs/qwen-gguf-runtime-local-build.md).

### Changed

- **Settings reorganized into sections** with a sticky navigation band and
  engine-conditional cards: VieNeu-only controls are scoped to their engine and
  the SRT picker is gated by capability, so the page only offers what the
  selected engine can actually do.
- **Editor metric chips are script-aware** — CJK text is counted in words and
  its duration estimated per script instead of assuming Vietnamese.
- **Clone identity hashes the decoded audio samples**, not container bytes, so
  the same clip re-encoded into another container is recognized as the same
  clone.
- **CUDA detection hardened** and the automatic backend resolution deferred
  until after the first paint, so startup no longer blocks on driver probing.

### Fixed

- **Cancel is honest and responsive**: cancelling no longer freezes the GUI and
  a cancelled generation never runs to completion.
- **A missing runtime no longer crashes prewarm or misreports readiness** — it
  reads as "not installed", which is what it is.
- **Downloads report real byte progress** (the model progress counter counted
  files, not bytes), and the managed runtime install stays linear while
  reporting its true size.
- **The app sends the language code to the host**, not the model name — which
  is what made audition previews speak the wrong language.
- **Qwen device hygiene**: CUDA runs at the locked `bfloat16` precision rather
  than `float32`; MPS releases its cache and falls back to CPU for ops the
  backend does not implement.
- **Windows**: `sox` ships with the runtime, an unimportable runtime is
  reported as a runtime problem rather than a crash, and pack staging handles
  multi-config MSVC layouts.
- **Studio dialogs** size from the dialog itself (capped width) instead of
  their content layout, so long transcripts no longer stretch the window.
- **Audiobook ETA** projects zero on the final tick instead of a stale
  estimate, and the Text tab shows a single Cancel button during synthesis.
- **VoicePicker** elides its trigger reason instead of clipping it, and
  destructive Settings actions are gated behind confirmation with clearer
  labels.

### Performance

- Streaming resampler position generation is vectorized, and the host's thread
  posture is pinned so inference threads no longer float with the machine.
- Measured on the shipped GGUF packs: on Apple Silicon (M4) **Metal runs faster
  than realtime** (RTF ≈ 0.48, first audio ≈ 0.66 s) and CPU is near-realtime
  (RTF ≈ 0.80, first audio ≈ 0.14 s); on the CI-built `linux-x64-cpu` pack CPU
  is slower than realtime (RTF ≈ 2.6 CustomVoice, ≈ 7 Base). Full numbers:
  [docs/performance/qwen-gguf-compatibility.md](../../docs/performance/qwen-gguf-compatibility.md).

### Internal

- **Release pipeline hardening**: the build now asserts the frozen bundle
  contains no PyTorch/Qwen stack *and* that the packaged binary can re-dispatch
  itself as either model host (`--qwen-host`, `--qwen-gguf-host`) — a frozen
  build has no `python -m` to hand the host half to.
- **CI split into parallel unit and smoke jobs**; new opt-in workflows:
  `qwen-runtime-smoke.yml`, `qwen-gguf-runtime-build.yml`,
  `qwen-gguf-runtime-smoke.yml`, `qwen-gguf-upstream-drift.yml` (weekly
  upstream pin drift check), plus the CUDA-runtime spike.
- **Two-tier validation**: ordinary CI stays deterministic and torch-free on
  scripted fake hosts, while the real model is exercised only through the
  opt-in `scripts/qwen_release_smoke.py` and `scripts/qwen_gguf_release_smoke.py`
  gates (the latter covering 6 cells × 4 variants = 24 combinations with
  identity, device, resource, cancellation, restart and shutdown evidence).
- English catalog completed for the new surfaces; `ruff check .` +
  `ruff format --check .` clean on 192 files, and the gate is
  **2262 passed + 1 skipped** (offscreen Qt, 2263 items selected of 2275
  collected, 12 benchmarks deselected).

### Evidence status — what is proven and what is not

This release does **not** claim more hardware validation than exists:

- **GGUF**: only `linux-x64-cpu` is probe-verified end to end today. The other
  five cells (`windows-x64-cpu`, `windows-x64-cuda`, `linux-x64-cuda`,
  `macos-arm64-cpu`, `macos-arm64-metal`) stay `pending` real-device evidence —
  the macOS cells have 1 of their 4 variant probes passing on an M4, and the
  CUDA cells have no runner at all. The packs are published and installable;
  the matrix flips to `verified` only when a cell's four probes pass.
- **Official (PyTorch) weights**: all six matrix cells remain `pending` until
  they run on provisioned hardware through the opt-in release smoke. Install,
  verification and offline-import paths are covered by tests; real-model
  numbers are not.
- **macOS builds are still ad-hoc signed** (no Developer ID configured) — first
  launch needs the Gatekeeper System Preferences → Privacy & Security →
  "Open Anyway" bypass.
