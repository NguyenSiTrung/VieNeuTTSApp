## VieNeuTTS v0.3.0 — Five-Destination Redesign, Responsiveness Hardening & Platform Fixes

v0.2.0 added the Qwen engines. This release changes how the app is laid out
and how fast it responds. The six-tab sidebar is now **five destinations**
organised around the voice: **Create** (Tạo giọng đọc), **Audiobook**
(Sách nói), **Voices** (Giọng đọc), **Studio** and **Settings** (Cài đặt).
The primary action stays in one pinned dock, and every screen works at the
640×420 minimum window. A performance audit also moved book loading,
exports, Studio and audition file I/O, subtitle dubbing and Qwen engine
preparation off the GUI thread, so the multi-hundred-millisecond freezes
are gone. Live preview no longer runs synthesis at playback speed. Packaged
builds start about twice as fast, because their QML is precompiled.

Engines, models and the dependency lock are unchanged (VieNeu SDK 3.3.0).
Existing settings, voices, clones, books and Studio projects carry over.

### Upgrade notes

- **macOS 14 (Sonoma) or newer is now required.** The bundle declares
  `LSMinimumSystemVersion 14.0`, which was already the real floor (the
  arm64 `onnxruntime` wheel is `macosx_14_0`). On older systems you now get
  a clear "requires macOS 14" message instead of a Qt dyld crash or an
  engine failure partway through a job. GGUF runtime packs refuse macOS
  versions below 13.
- **Source installs need PySide6 ≥ 6.9** (previously ≥ 6.7). Card shadows
  use QtQuick.Effects `RectangularShadow`. The lock already resolves 6.11.2.
- Navigation ids changed (`create`, `audiobook`, `voices`, `studio`,
  `settings`). The legacy ids `text`, `paragraph` and `cloning` are still
  accepted and map to Create → Compose, Create → Document and Voices →
  Clone.

### Added — Five-destination shell

- **Create (Tạo giọng đọc)** replaces the separate Text and Paragraph tabs.
  A mode switch (**Compose / Document / Multiple files / Subtitles**) sits
  over one shared **TransportDock**: a voice chip, *Generate* (Ctrl+Enter),
  which turns into *Stop* (Esc) while busy, playback with waveform and
  timecodes, an export split button (WAV/MP3, quick save, save as…), and
  *Open in Studio*. Emotion tags appear as chips in the compose toolbar.
- **Create inspector**: a card for the current voice with audition and
  *Change voice…*, the **three most recent voices** (stored separately for
  each engine profile), per-run speed and sentence-pause sliders, and the
  live-preview toggle, which now has exactly one location. The inspector
  is a 300 px column at ≥ 1000 px and moves under the editor on narrower
  windows.
- **Voices (Giọng đọc) library**: the preset voices grouped by region
  (Bắc / Trung / Nam), with gender and style filters, search that ignores
  diacritics, audition on every row, *Set as default*, and a section for
  cloned voices. Voice cloning now lives here as the clone view; its
  privacy and consent notice is unchanged. *Change voice…* in Create opens
  the library in pick mode. Each row then gets *Use this voice*, which sets
  the voice and returns you to Create.
- **Audiobook (Sách nói) master–detail**: a library column of book tiles
  (progress, author · chapter count, drop target) and a book detail whose
  chapter list fills the full height and is the only scroller. The nested
  360 px scroll inside the page scroll is gone. At ≥ 1200 px the reader
  docks as a third column. The player uses the dock skin (44 px prev/next
  around a larger play button, *Auto-advance chapters* inside the player),
  and chapter row actions have accessible names.
- **Studio**: clips appear as duration-proportional blocks on a timeline
  with a selection and a playhead. A row of history chips offers undo and
  reset. A new **Effects (Hiệu ứng) panel** keeps edits *pending*: you can
  preview them, A/B them with an **Original / Edited** toggle, and commit
  them all with a single **"Apply N changes"** button that counts as one
  undo step. This replaces the per-row *Apply* buttons. The empty state
  points to Create, Document and Audiobook.
- **Settings (Cài đặt) sub-navigation**: six sections (General, Voice &
  pacing, Export, Engine & hardware, Models, Updates) and a label filter
  that ignores diacritics. The engine section starts with a summary card:
  current state, active backend and precision, why it was chosen, and an
  **Auto / CPU / GPU** switch. Precision, the managed CUDA runtime, the
  Qwen device and diagnostics sit under collapsed *Advanced* disclosures.
  The CUDA auto-expand rules are unchanged. The default-voice setting is
  now a read-only row that links to the Voices library.
- **Bottom status bar**: model/engine readiness, the engine note (backend ·
  precision · mode), the audio-output state with *Check again*, and the
  update indicator. It replaces the floating export-only pill and the
  sidebar engine card, and never shows an empty or "…" value.
- **Sidebar**: Create, Audiobook, Voices and Studio at the top, Settings
  pinned at the bottom with the update dot. Below 800 px it becomes an
  icon-only rail with tooltips and accessible names.
- **Settings → Verify files**: re-hashes installed Qwen runtime and model
  files in the background on request and reports what it finds. Findings
  persist, so later quick checks keep reporting them.

### Added — Audiobook

- **Oversize chapters are split automatically.** A chapter over the
  60,000-character limit used to be refused and produced no audio. It is
  now split at paragraph and sentence boundaries into deterministic parts
  (`ch_XXXX_sYY.wav`). The parts render in order under the same chapter,
  play back to back, and export as ordered part files.

### Changed — Design system

- **Accessibility floor**: no rendered text below 12 px, every interactive
  target at least 44 px, and subtle text that passes WCAG AA (4.5:1) on
  every surface in both themes. A smoke scan checks rendered sizes for
  every destination.
- **Quieter chrome**: page headers are a single row (no icon tile, no
  subtitle). Cards drop their subtitle and header divider. Settings rows
  lose their decorative icon tiles.
- **Button hierarchy**: one primary action per screen state, disabled
  controls never look filled, "Studio…" is now **"Open in Studio"**, and
  clearing the editor can be undone (Ctrl+Z).
- New **segmented control** for Color mode, Create modes and the device
  pickers.
- **640×420 minimum window**: the dock condenses to icon-only actions, the
  files queue fills the visible height, the voice filters share a row, the
  audiobook detail compacts, and Settings swaps its chip navigation for a
  section dropdown.

### Performance

- **No more GUI-thread stalls.** These now run in the background, with busy
  and progress states: opening and refreshing books, *Export all* and
  per-chapter audiobook exports (the book is loaded once per run, and a
  second export is refused while one runs), Studio chapter import and clip
  preview, the audition cache copy, CUDA readiness probes, subtitle dub
  placement (on an ordered worker while the next unit synthesizes), and
  Qwen engine preparation (submissions queue until the engine is ready).
- **Live preview runs at engine speed.** The worker no longer waits for
  playback. Audio that does not fit the 2 s live buffer is read back in
  order from the on-disk part file, so playback stays sample-exact and the
  job finishes as fast as the engine can render it.
- **Qwen live jobs start sooner**: smaller first segments (150 and then 250
  characters, cut at clause marks), and the host prefetches the next
  segment while the current one plays. It never runs more than one job
  ahead.
- **Lower per-job Qwen host overhead**: accelerator caches are released
  every 8 jobs (or after 512 MiB of RSS growth) instead of after every job,
  generation runs under `torch.inference_mode`, footprint reads use
  `/proc` on Linux, and the GGUF host reuses reference-clip digests while
  the file is unchanged.
- **Install checks skip full hashes for unchanged files.** `install.json`
  records size, mtime and inode stamps. Routine engine builds trust a
  matching stamp, and only changed files are re-hashed. *Verify files*
  always re-hashes everything.
- **BLAS thread cap of 1 by default.** OpenBLAS threads sized to every core
  competed with ONNX Runtime's threads: warm VieNeu RTF went **1.43 → 0.80**
  and process CPU went 208% → 123% on a 4-core host (+130 MB peak RSS).
  Environment variables you set yourself still take precedence, and Qwen
  hosts keep their own thread defaults. Evidence:
  [docs/performance/tuning-vieneu.md](../../docs/performance/tuning-vieneu.md).
- **Faster startup in packaged builds**: QML is precompiled at build time.
  On a cold first launch, first frame went **~605 → ~296 ms** (median) and
  all tabs were ready in ~1377 → ~1062 ms. Only the landing destination is
  built before the first frame; the others load asynchronously, either on
  first visit or in an idle prebuild.
- **Long lists update row by row.** Chapters, subtitle cues, batch items
  and Studio clips/ops use diffing list models. Progress ticks no longer
  rebuild every delegate or lose the scroll position.
- **Rendering**: waveforms repaint only when visible and changed (a
  playhead tick repaints nothing), icons no longer use one framebuffer
  each, and card shadows are analytic instead of a blur pass per card.
- **Audio**: WSOLA speed changes use FFT cross-correlation (≥ 3× on 60 s,
  output identical within float rounding). Studio caches the time-stretched
  mix, so edits after a speed change do not re-stretch it. Multiple-file
  runs encode the finished file while the next one synthesizes.
- **Smaller wins**: prewarm also warms text normalization and the
  phonemizer, so the first job skips their cold start. Word-count and
  duration metrics are debounced. The subtitle dub policy rebuilds only
  when you release the slider. Qwen PCM framing is vectorized, and the live
  transport drops a redundant copy.
- **Benchmark-only engine knobs** (no UI, defaults unchanged): ONNX Runtime
  threading, export-sized codec chunks and batched PyTorch export. They
  exist so the tuning matrix can measure them; none is enabled until
  evidence supports it.

### Fixed

- **Live playback on Int16-only audio devices**: live PCM is now converted
  to the format the device negotiated, instead of being played as raw
  float32.
- **Windows: native GGUF path hardening.** `qwen.dll` receives ASCII-safe
  paths (the 8.3 short name, or an actionable error) when your profile
  folder has non-ASCII characters. Native stdout writers can no longer
  corrupt the host's framed protocol. Process liveness checks use
  `WaitForSingleObject`, so they are no longer fooled by exit code 259 or
  truncated handles. Wheel extraction and downloads are safe past
  `MAX_PATH`. Runtime links fall back to hardlinks or copies when symlinks
  are denied, and are verified by content. The import-check subprocess no
  longer flashes a console. Retry windows for antivirus and OneDrive file
  locks are longer.
- **macOS: HTTPS in packaged builds.** Frozen builds had no CA store, so the
  update check and GGUF pack downloads could fail with
  `CERTIFICATE_VERIFY_FAILED`. The app now ships certifi's bundle and
  points `SSL_CERT_FILE` at it when that variable is unset.
- **macOS: visible startup errors.** Second-instance and fatal startup
  errors now show a native alert. Before, they went to an invisible stderr
  and looked like "the app won't open".
- **`file://` URLs**: `file://localhost/...` resolves to the local path, and
  `file://host/...` becomes a `//host/share` path on macOS/Linux (UNC
  conversion is Windows-only). Spaces, `#`, `?`, `%` and non-ASCII
  characters are now percent-encoded, so dialogs no longer truncate
  Vietnamese filenames.
- **macOS DMG** now includes an `/Applications` shortcut for drag-install.
- An invalid audition artifact no longer falls through into playback.

### GGUF runtime

- The `qwentts.cpp` pin moved to **`6fae9291`** (ggml 0.25.3; the ABI
  version is unchanged at 5). The four published packs (`windows-x64-cpu`,
  `linux-x64-cpu`, `macos-arm64-cpu`, `macos-arm64-metal`) were rebuilt in
  CI and re-locked at that pin. CUDA packs are still unpublished (no GPU
  runner), and the local build recipe in
  [docs/qwen-gguf-runtime-local-build.md](../../docs/qwen-gguf-runtime-local-build.md)
  still applies.

### Internal

- **CI runs only at release.** The per-commit workflow is gone. The
  tag-triggered Release workflow still runs ruff and the full suite on
  Windows, macOS and Ubuntu before building, so a failing gate still blocks
  publishing. `gh workflow run Release` remains the dry run. The release
  build also asserts that every bundled `.qml`/`.js` ships its precompiled
  unit.
- **Leaner test suite**: tautological, duplicate and static-pin tests were
  pruned, micro-tests of the same function were merged (every assertion
  kept), smoke scenarios now share QML windows, and fixed sleeps became
  event-driven waits. xdist uses `worksteal` scheduling. A full run dropped
  from about 175 s to about 55 s. `pytest-cov` and the coverage threshold
  were removed.
- An offscreen screenshot matrix script (destination × theme × size)
  regenerates the README screenshots, which now show the redesigned UI.
- Gate for this release: `ruff check .` and `ruff format --check .` clean
  (202 files). Local pytest on linux-aarch64 (offscreen Qt): **1891
  passed, 4 skipped**, plus 7 GGUF tests that fail only because that host
  has no GGUF runtime cell. Those tests assume a supported host and will
  be made to skip. The Release workflow runs the full suite again on
  Windows, macOS and Ubuntu before it publishes anything.

### Evidence status — what is proven and what is not

- **GGUF**: the probe evidence published with v0.2.0 was recorded against
  the previous pin's packs, so it does not apply to the rebuilt packs. All
  four published cells are now **pending re-verification** through the
  opt-in release smoke. The packs are built and checksum-locked in CI, but
  no probe or real-device numbers have been re-recorded at the new pin yet.
- **Official (PyTorch) weights**: all six matrix cells are still `pending`
  real hardware.
- **Engine tuning** was measured on one 4-core Arm Linux host. Other
  hardware classes have not been measured, which is why only the BLAS cap
  changed by default.
- **macOS builds are still ad-hoc signed** (no Developer ID). On first
  launch, use System Settings → Privacy & Security → "Open Anyway".
